# 按品牌自动检索知识并生成文章

日期：2026-08-26
状态：用户已确认书面规格并授权实施；实现进度见同日期实施计划。

## 1. 目标和边界

任务创建、Excel 批量导入、手动内容简报统一使用：

选择品牌一级目录 → 限定品牌内有效资料 → 按主题、关键词、核心问题检索 → 去重排序 → 保存证据快照 → 生成。

运营不用逐一填写具体知识库名称。知识与关键词不要求预先绑定；关键词关联只作为可选排序信号，不作为召回的必需条件。文章标题库仍是选题输入，最终标题沿用现有质量门禁生成及采纳逻辑。

本次不开发商品导入、商城爬虫、热销判定、WordPress 发布改造，不迁移或删除现有知识，不重写已发布文章。

## 2. 已核实的现状

- 已有 KnowledgeBrand、KnowledgeSite、KnowledgeDirectory 和 KnowledgeScope。
- KnowledgeRetrievalService 已有品牌、来源站点、语言、active、generation_eligible 过滤，但目录是精确匹配；多知识库入口仍截断为 5 个。
- 任务质量门禁入口按所选知识库取前几个已审核切片，并非按主题检索。
- 简报页面提供全局最近 100 个已审核切片，未按品牌隔离。
- 生成快照服务检查 reviewed，但仍需补充品牌、来源站点和有效性检查。
- 批量模板要求具体 knowledge_base 名称，同名记录存在歧义风险。

因此不能只把下拉框名称改成“品牌”，必须统一服务端检索和快照校验。

## 3. 方案选择

采用共享的品牌范围解析及证据选择服务，复用现有检索评分和快照机制。

不采用“各页面分别增加过滤”的方案：后台任务可能绕过页面限制，三条路径容易产生不同结果。也不把全品牌知识直接拼进提示词：这会增加成本，并注入无关甚至冲突资料。

## 4. 范围与持久化

界面“品牌一级目录”对应 KnowledgeBrand，而不是把目录显示名称当作隔离键。可选 KnowledgeDirectory 子目录，包含其全部后代；服务端校验整条目录归属，拒绝其他品牌目录。

Task 和 ContentBrief 增加可空的品牌、来源站点、目录范围及检索模式字段。新记录默认 brand_auto；旧记录保持 legacy_manual，不自动猜测历史归属。brand_auto 必须指定品牌。旧任务仍支持原来的最多 5 个显式知识库选择。

来源站点 KnowledgeSite 与发布渠道 DistributionChannel 是不同概念，不能用测试 WordPress 域名代替商城知识来源。品牌仅有一个来源站点时自动解析并保存；没有来源站点则报错，有多个则要求明确选择，不取第一条。品牌或目录变更后清空旧证据预选。

语言使用简报的明确语言；任务通过既有预设默认值形成简报时固化语言。当前默认英文，不在无结果时自动混入其他语言。

## 5. 检索与证据选择

统一请求包含范围、主题、可用的主次关键词、核心问题，以及用户额外选中/排除的切片 ID。

1. 查询前限定品牌、来源站点、语言、可选目录及其后代。
2. 仅纳入 reviewed、active、generation_eligible 的资料；已有有效期字段表示尚未生效或过期时排除。未知日期不能解释为已确认新鲜。
3. 在范围内进行词法及向量候选召回，复用现有打分。不能先全局召回再裁剪品牌。
4. 按规范化内容哈希去重，同文档版本优先有效版本；权威性和时效作为排序信号，不能代替主题相关性。
5. 新增品牌范围入口，不经过旧入口的 take(5)，同时设置全局候选和证据预算，不能无限加载所有切片。
6. 默认最多选 12 个片段、总计最多 24,000 字符；片段以完整单元装入预算。单片段超限则标记需重新切分，不静默截断政策句子。手工调整仍受同一预算及最多 50 个 ID 的请求校验约束。
7. 仅元数据匹配、无正文/标题相关性且无合格向量相似度的片段不自动选入。向量阈值与模型绑定，通过固定相关/不相关样本确定，不假定不同模型的分数可直接比较。

实施说明：当前没有校准过的向量阈值，本版仅启用词法召回并返回明确提示。向量独立召回暂缓；代价是语义改写可能漏召回，而不是接受未经验证的相似度作为事实证据。

返回结果包含真实 chunk ID、知识库 ID、品牌/站点/目录、标题、来源链接、相关性分数及组成、内容哈希、可用版本/日期和不足原因。未知来源信息保留为空，不制造链接或日期。

无合格证据时显示“该品牌内证据不足”，阻止 brand_auto 的付费正文生成；不跨品牌补齐，不退回无证据生成。部分证据不代表问题全部得到验证，提示词必须约束未支持的事实不作断言。

## 6. 快照、调整与重试

简报展示自动匹配证据、来源和不足提示，允许重新检索、勾选同范围证据或排除结果。排除操作在排序后生效，不能被自动补充再次加回。

正式预留生成运行时再次校验所有切片的范围、审核、状态及有效性；不能只依赖前端列表或早先预览。显式提交的越界 ID 必须报错，不能静默忽略。

证据快照记录最终内容、内容哈希、来源、范围、检索输入、排序结果及选择方式。生成只读此次快照。相同幂等键复用原运行和原快照，不因资料更新再次检索；明确重新生成使用新运行、新快照。

brand_auto 不接受通过自由文本 evidence 绕过隔离。现有 URL/外部证据能力保留在旧流程；未来要用于 brand_auto，须独立增加带归属和审核的导入流程，本次不隐式开启。

旧任务保持显式知识库检索路径，但不能把不兼容的跨品牌资料拼在一起；发现范围不一致时给出迁移提示。既有快照不追溯修改。

## 7. 三个界面

### 任务创建/编辑

新增品牌一级目录选择，可选子目录；来源站点唯一时自动显示。brand_auto 隐藏逐个知识库选择及“最多 5 个”文案。旧任务显示兼容模式，可由用户主动切换。质量门禁任务复制范围到简报；传统生成任务也调用同一证据选择服务，按其运行记录保存证据审计。

### 内容简报

创建时选择品牌范围，生成区域提供“匹配知识”及证据列表，不再显示全局最近 100 个切片。直接调用生成接口也执行同样的范围校验；不依赖用户先点击预览。

### 批量导入

新模板以 brand 必填列替代 knowledge_base，directory 和 knowledge_site 可选；品牌使用稳定 key 或“名称 (key)”并提供参考表。缺失、重复名称或跨品牌目录均在导入前逐行报错。来源站点多于一个时要求 knowledge_site。

保留旧模板解析，明确标注兼容模式；同一行混填 brand 与 knowledge_base 报错，避免不明确的优先级。分组键包含发布站点、预设、文章分类和完整知识范围，防止不同品牌合并成同一任务。全部验证后再事务性建任务。

商品图片、价格和新品时间不属于此次模板变更。

## 8. 验收与测试

- 品牌 A 与 B 含完全相同主题时，A 的检索、手工选择、任务和快照均不能出现 B。
- 同品牌不同来源站点不能互串；发布渠道变化不改变知识来源。
- 父目录包含后代，不包含兄弟目录或其他品牌同名目录。
- 未审核、停用、不可生成、过期、未来生效及错误语言资料不能入选。
- 第 6 个及以后知识库的相关资料可被新流程召回。
- 同内容去重、无关片段排除、预算限制及证据不足阻断均有测试。
- 手动越界 ID、过时预览、自由文本绕过均被服务端阻止。
- 幂等重试复用原快照；新运行可获取更新后的资料。
- 新旧 Excel 模板、歧义名称、不同范围分组、失败事务回滚均有测试。
- 同主题/范围从三个入口生成时采用相同证据选择规则。
- 保留旧任务兼容测试；自动化测试使用模型替身，不消耗真实 API 额度。

实施阶段先补失败测试，再实现；使用当前 Docker 对应 worktree 验证。不覆盖工作区已有的种子命令、其测试和 docker-compose.yml 修改。本规格不授权向正式站发布或推送远程仓库。
