# 分类关键词贯通标题与知识检索

状态：用户认可总体方向；本规格待书面确认。

## 目标与现状

让运营控制标题和文章的商品主题，并修复标题随机绑定关键词及品牌知识错误召回。沿用现有关键词库、KeywordNode 分类树和 KeywordCluster，不重新分类原始数据。

已核实：标题生成页面只选关键词库；后端全库随机抽词；保存标题时再次随机选 keyword。Title 没有关键词 ID/分类来源；任务仅传递自由文本 keyword。原有 KnowledgeRetrievalService 支持混合检索，但无可靠主题准入门槛；新增品牌选择器的两词匹配会把 of/on/know 当有效命中。发布分类不等于关键词分类。

## 选择与边界

采用贯通关联方案，而非仅增加下拉框或另建一套关键词库。只加下拉框仍会留下标题随机绑词和下游关联丢失；另建库会重复既有分类资产。

本次不修改已发布文章、不批量纠正旧标题、不删除知识、不自动启用资料、不自动重试现有付费运行。模型上下文预算/提示词审计字段精简为独立问题，本次不靠放大预算掩盖无关召回。

## 标题生成入口

- 先选关键词库，再选该库实际有关键词关联的分类树节点；支持 L1–L4，可选包含后代。节点不符合该库范围时服务端拒绝。
- 默认英文，可选择语言；搜索意图为可选过滤。只选 active 的规范关键词，不混入其他语言或失效词。未分类词必须明确选择“未分类”，不偷偷混入分类范围。
- 可选主题簇必须属于所选范围；跨分类的辅助词不扩大候选范围。
- 展示符合筛选的总数和有界候选预览，允许勾选实际用于生成的词；无结果不退回全库。
- 预览和提交共用筛选服务。提交重新校验所选 ID，防止资料变化或伪造请求扩大范围。
- 每个词携带 keyword_id、文本、分类路径、语言、意图和可选簇信息。标题数保持现有上限50，单次关键词候选上限保持现有配置；不因标题数增加而扩大词库范围。

## 标题与关键词真实对应

- 新生成入口要求模型输出结构化条目：title、keyword_id、core_question。keyword_id 只能来自提交的候选集合。分类/簇由服务端根据已验证选择记录，不能信任模型自行填写。
- 一个标题对应一个主关键词，可以多标题对应同一词；不得随机分配，也不能按输出顺序猜配。
- 为保证首版可验证，新标题必须包含主关键词或该规范组内已记录的同语言等价变体；不把任意语义近似自动视为等价。代价是部分自由改写会被拒绝，可调整标题或选词后重试。
- 非法 ID、明显错配或无法解析的模型输出不入库，显示可理解的原因；不静默用中文模板冒充英文 AI 结果。不额外自动发起付费修复调用。
- 保留旧 generateTitles 调用契约供既有调用方兼容，新入口采用结构化返回路径。模板兼容调用不随机改变已确定词与标题的对应。
- Title 新增可空主关键词、分类节点、主题簇、语言及来源快照；保留 keyword 文本兼容旧导入。外键删除不会删除标题，来源快照保留历史含义。
- 标题列表展示主关键词、分类路径、语言及关联是否完整，便于运营检查。

## 任务与简报

- 新建/编辑任务可在标题库内限定关键词分类及后代；显示符合范围的可用标题数。已有任务不静默修改范围。
- 已筛选任务只消费符合范围且关联有效的标题；没有符合标题时提示耗尽，不退回其他分类。
- 标题主关键词 ID、可选簇、语言和分类来源复制到简报；用户指定的品牌知识边界仍然优先，关键词不得扩张品牌、来源站点或语言范围。
- 已结构化的标题不得重新由自由文本随机/猜测绑定。旧标题保留，但不能因旧 keyword 文本存在就假定可信；标题与词明显不一致时，品牌自动生成提示修正，不能付费生成。
- 文章发布分类继续使用明确的固定分类，不由商品分类自动猜测。任务页面明确说明现有非固定分类并不提供语义智能分类；本轮不增加跨 WordPress/Shopify 分类映射系统。

## 主题相关检索

- 复用原有 KnowledgeRetrievalService 的候选检索、词法/标题评分和可用向量能力；品牌选择器保留范围验证、预算、去重、锁定复验和不可变快照职责，避免再保留两套不同词法评分。
- 查询主轴是经验证的主题关键词及已记录同语言变体；标题、核心问题仅补充意图。移除功能词和模板套话，不把整句中的两个普通词作为准入依据。
- 自动证据必须包含主题关键词的有效实体/品类词，或有已验证同义词依据；来源、品牌和时效加分只能在相关候选间排序，不能把无关资料变成相关。未校准的向量分数不能单独越过主题门槛。
- 不要求给知识库预先绑定关键词节点。知识分类可作辅助线索，但“同一品牌/同一目录”不能替代正文相关性。
- 假发通用资料只能支持假发通用建议；不能证明 Rumi 的具体材质、价格、使用效果。专属评测缺乏产品证据时显示缺口，阻止无依据的产品评测生成。
- 记录实际匹配词、分数组成和来源，页面能解释为何命中。无相关证据返回不足，不凑满片段预算，不回退捐赠/疫情资料。
- 保持同一幂等运行复用既有快照；新规则作用于新运行，不能覆盖旧审计。

## 验收与安全

1. 选 Wigs 分类后，候选不出现 bags and handbags；包含后代正确，兄弟分类不进入。
2. 修改分类/语言后清空不适用的预选；伪造分类、词和簇 ID 在模型调用前被拒绝。
3. 模型返回标题与主词的有效对应；非法/错配结果不落库，不再调用 random 绑定。
4. 任务分类范围贯穿标题选择和简报，正确保存主词及语言，固定发布分类保持不变。
5. Rumi 假发选题不召回 Donate1258/Covid1308；只含 of/on/know 的资料不通过；真正的假发指南仍可作为通用证据，但不能被升级为产品评测事实。
6. 品牌/站点/语言/有效性隔离、并发重验、幂等快照及旧模板回归保持。
7. 自动化测试使用模型替身，不消费 API；仅在本地备份后应用新增迁移，不执行无关迁移/种子。真实付费生成由运营明确触发。
8. 保留当前 seed命令/测试、docker-compose和交接文件中的既有改动，不推送远程、不打开浏览器。
